## 2026-05-18 - [CRITICAL] Fix SSRF IP Parsing Bypass
**Vulnerability:** The URL validation logic in `_validate_ssrf_safety` used `ipaddress.ip_address` to block loopback and private IP addresses. However, `ipaddress.ip_address` strictly requires dotted-quad formatted IP strings. Attackers could bypass this check by passing octal (e.g., `0177.0.0.1`), hexadecimal (e.g., `0x7f.0.0.1`), short-form (e.g., `127.1`), or integer formats (e.g., `2130706433`), which standard network libraries (like `urllib` or C networking stacks) interpret as `127.0.0.1`.
**Learning:** `ipaddress.ip_address` does not catch all valid IP formats supported by underlying system network APIs, leading to critical SSRF bypasses when used alone for validation. The environment has a strict prohibition on active DNS resolution during validation (the Air-Gap Mandate), so we couldn't use `socket.gethostbyname()`.
**Prevention:** Normalize all IP inputs using `socket.inet_ntoa(socket.inet_aton(hostname))` before passing them to `ipaddress.ip_address`. This normalizes integer/hex/octal representations into dotted-quad IPv4 natively without triggering DNS resolution, effectively sealing the bypass.
