## 2025-02-20 - SSRF Filter Bypass with Alternative IP Encodings
**Vulnerability:** The SSRF protection in `_validate_ssrf_safety` used `ipaddress.ip_address` strictly to parse hostnames. Alternative IP encodings like hex (e.g. `0x7f000001`), octal (e.g. `0177.0.0.1`), or integers (e.g. `2130706433`) threw a `ValueError` which the function caught and then bypassed the IP check entirely, returning the URL on the assumption it was a hostname that couldn't be resolved because DNS lookups were explicitly forbidden ("Air-Gap Mandate").
**Learning:** Security validations on URLs must handle all standard canonicalizations of IPv4 representations supported by the underlying HTTP clients. The `ipaddress` library is strict by design and should not be solely relied upon to handle URL hostnames.
**Prevention:** Use `socket.inet_aton(hostname)` to catch non-standard IP formats in `_validate_ssrf_safety`. This translates alternative IP encodings to their canonical byte representation, which can then be parsed safely via `ipaddress.IPv4Address(packed)`. Furthermore, ensure that the exception handling specifies strictly `(OSError, TypeError)` rather than catching generic Exceptions to avoid hiding bugs.
